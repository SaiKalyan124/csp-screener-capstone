Iteration roadmap

Each iteration adds capability without moving financial calculations into the language model.

Iteration 1

Deterministic CSP screening

  • Batched Alpaca market data
  • Explicit eligibility and scoring
  • Top-ten dashboard and ticker chain
  • Cache and scheduled refresh
  • Deterministic core requires no LLM; Iteration 2 can enrich its results
Iteration 2

CSP Research Intelligence

  • Top-10 research classification
  • Favorable · Watch · Avoid · Insufficient evidence
  • Advanced company-evidence RAG
  • Comparisons and budget-aware discovery
  • Citations, Arize traces, and evaluations
Iteration 3

Profile, memory, and positions

  • User preferences and constraints
  • Session and durable memory
  • Portfolio-aware strategy routing
  • Alerts and monitored research
  • Explicit safety confirmations

Current implementation: UI → HTTP API → application service → deterministic workflow/research graph → Alpaca SDK provider, plus an in-memory cache and Arize tracing. MCP, hybrid RAG storage, vector indexing, and durable profile/memory storage are end-state additions.
Deterministic authority

Eligibility, scores, Greeks-derived values, affordability, and contract calculations are code controlled.

Bounded intelligence

The model classifies the eligible Top 10, retrieves, compares, explains, and abstains. It cannot admit rejected candidates or rewrite formulas.

Evidence before synthesis

Material claims must point to market state or retrieved passages with visible source and freshness.

Dashboard screening and research sequence

Code establishes eligibility and scores first; a bounded research pass then classifies only the deterministic Top 10.

sequenceDiagram
  autonumber
  participant User
  participant UI as Dashboard UI
  participant API
  participant App as Application service
  participant Cache
  participant Screen as Deterministic workflow
  participant Provider as Alpaca provider/MCP
  participant Research as Bounded research workflow
  participant Evidence as Filings + news
  participant Model as Structured LLM call
  participant Arize
  User->>UI: Open dashboard
  UI->>API: GET /api/screen
  API->>App: screen(force=false)
  App->>Cache: Read latest validated snapshot
  alt Fresh snapshot exists
    Cache-->>App: Combined Top ten + research metadata
  else Missing or manual refresh
    App->>Screen: Run configured universe
    Screen->>Provider: One batched daily-bars request
    Provider-->>Screen: Timestamped bars
    Screen->>Screen: Hard-filter and rank stock pool
    Screen->>Provider: Validate bounded chains for ranked pool
    Provider-->>Screen: Quotes · IV · Greeks · timestamps
    Screen->>Screen: Require five eligible CSPs + five eligible calls
    Screen-->>App: Fully eligible Top ten + cached chains
    App->>Research: Invoke dashboard LangGraph
    Research->>Evidence: Retrieve shortlist evidence in parallel
    Evidence-->>Research: Filing metadata + news
    Research->>Model: One LangChain structured-output call
    Model-->>Research: Favorable · Watch · Avoid · Insufficient evidence
    Research->>Research: Validate + run code-based evaluations
    Research-->>App: Labels + citations + evaluation scores
    App->>Cache: Atomically publish combined snapshot
    Screen-->>Arize: Latency · counts · cache · errors
    Research-->>Arize: Retrieval · model · classification · fallback
  end
  App-->>API: Screen response
  API-->>UI: Scores + research labels + timestamps + warnings
  UI-->>User: Render dashboard
If research retrieval or the model fails, the deterministic Top 10 remains available and is explicitly marked as a fallback. Research may group eligible results but cannot change scores or restore a rejected ticker.

Profile and memory model

Memory is separated by purpose so the model receives only the context required for the current route.

flowchart LR

  E[(Episodic memory

  PR[(Procedural memory

  R[Context policy]
  G[LangGraph route]
  U --> W
  P --> R
  W --> R
  E --> R
  PR --> R
  R -->|minimum necessary context| G
  G -->|explicit updates only| P
  G -->|session checkpoint| W
  G -->|saved research| E
Working

Short-lived context for the active conversation and screen.

Durable

User-approved facts and saved research with retention and deletion controls.

Scoped

Not every route receives every memory type; portfolio data is never included unnecessarily.

9

End-state implementation summary

The final system remains modular: each layer can evolve without weakening deterministic finance or safety boundaries.

User experience

One coherent dashboard, ticker screener, research panel, and profile experience.

Financial core

Explainable rules, bounded provider calls, readable contracts, and reproducible results.

Research intelligence

LangGraph routing, Advanced RAG, structured synthesis, citations, and follow-ups.

Data foundation

Market state, canonical documents, vector and keyword indexes, profiles, and memory.

Reliability

Validated snapshots, caching, freshness, failure isolation, telemetry, and regression evaluation.

Trust and safety

Read-only capabilities, explicit uncertainty, privacy controls, and no autonomous trading.
